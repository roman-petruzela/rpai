# JARVIS

A local personal AI assistant built with Rust, Axum, SQLite and Ollama.

## Requirements

- Rust toolchain (`rustc` and `cargo`)
- Ollama running locally
- Ollama models: `llama3.1:8b` and `nomic-embed-text`

## First-time setup

```bash
chmod +x setup.sh
./setup.sh
```

The setup script checks Ollama, pulls the required models, runs `cargo check`, and builds the application.

Optional steps:

```bash
SETUP_PYTHON=true ./setup.sh
START_DOCKER_SERVICES=true ./setup.sh
```

## Run

```bash
cargo run
```

Open <http://127.0.0.1:3000>.

## Configuration

Environment variables:

- `OLLAMA_HOST` — Ollama base URL. Default: `http://127.0.0.1:11434`.
- `JARVIS_ADDR` — HTTP bind address. Default: `127.0.0.1:3000`.

To expose the server on the local network, set `JARVIS_ADDR=0.0.0.0:3000`. Do this only on a trusted network and add authentication/firewall rules before exposing it more broadly.

## Main components

- `src/main.rs` — application startup and routes.
- `src/ollama.rs` — chat handlers, prompt construction and SSE streaming.
- `src/db.rs` — profile, project knowledge and conversation history.
- `src/memory.rs` — automatic memory curation, embeddings, semantic recall and memory deletion.
- `src/search.rs` — DuckDuckGo HTML search.
- `static/index.html` — browser interface.
- `setup.sh` — local development setup.

## Memory behavior

After a successful response, JARVIS schedules a separate model call to decide whether the user's message contains useful long-term information. Accepted memories are embedded with `nomic-embed-text` and stored in SQLite. Relevant memories are retrieved for later prompts.

The curator is instructed not to store credentials or sensitive personal information. Since memory extraction is model-based, it is not infallible. Review and delete stored memories when needed. The code exposes memory list/delete functions internally; a user-facing memory management API is a future addition. The memory initializer also adds the new columns to the earlier `sector_memory` table format without deleting existing rows.

## Notes

- SQLite database file: `rpai.db` (ignored by Git).
- `Cargo.lock` should be generated by Cargo and committed for this application.
- DuckDuckGo HTML markup may change; search parsing may need maintenance.
- The current SQLite access uses a synchronous mutex. For heavier concurrent use, move database work to `spawn_blocking` or adopt an async database layer.
